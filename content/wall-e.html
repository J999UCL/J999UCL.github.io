WALL-E is a desktop-automation system in which a supervising agent delegates work to agents on separate Windows virtual machines. I built it to explore what a small “virtual office” needs beyond a chat interface: individual desktops, shared results, observable progress and a way to stop or recover work.

Separate planning from execution

The Python/FastAPI backend provisions Azure Windows VMs and coordinates their worker agents. Each VM runs a C# server exposing Windows UI Automation through the Model Context Protocol. Workers can inspect interface elements, click, type, launch applications and capture screenshots. A Guacamole desktop stream lets the user watch the machine directly.

The supervisor handles high-level instructions and delegation; workers handle individual desktops. For structured workflows, a planner produces a dependency graph through a typed tool call. A deterministic scheduler then runs nodes when their dependencies are satisfied, with bounded concurrency, retries, timeouts and cancellation. Results are written to a shared artifact store so later steps can use earlier outputs.

Keep the work visible

I implemented high-level delegation and interruption tools, action verification, and the session plumbing around them. Server-sent events expose progress and tool activity. Persisted event IDs allow a reconnecting client to recover recent activity, while a browser disconnection does not automatically cancel the underlying run. Per-VM chat sessions keep worker details separate from the supervisor conversation.

The main engineering challenge was coordinating application state, remote-machine state and agent state without treating them as one opaque process. Explicit task states and shared results make failures inspectable, while deterministic scheduling keeps dependency and cancellation rules outside the model’s reasoning loop. The repository includes bootstrap and end-to-end tests for the connection and execution paths.
